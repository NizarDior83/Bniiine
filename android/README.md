# Bniine — Android build

This folder ships the same Bniine game as the web version, wrapped in [Capacitor](https://capacitorjs.com) for a real Android APK / AAB. All hand-drawn assets (chef faces, ingredients, backgrounds, lantern, coin, trophy, palm fronds, etc.) are bundled under `www/assets/` and load offline from the APK.

## Fastest path: let GitHub Actions build the APK for you

If you don't want to install Android Studio locally, the repo has a workflow that builds the APK in the cloud:

1. Go to **Actions** on the repo page
2. Click **Build Android APK**
3. Click **Run workflow** (top right) → **Run workflow**
4. Wait ~5 minutes for the run to finish
5. Open the completed run and download the `bniine-debug-apk` artifact — it's a `.zip` containing `app-debug.apk`
6. Copy the APK to your phone and install (enable "Install unknown apps" for whatever you sideload with)

The workflow also fires automatically on every push to `main` that touches the game code, so every commit produces a fresh APK you can download.

The steps below are for building **locally** if you prefer to iterate faster or need a signed release build.

## What sits in this folder

```
android/
├── package.json                 npm scripts + Capacitor deps
├── capacitor.config.ts          app id, splash, status bar, orientation
├── AndroidManifest.overrides.xml  reference settings to merge into the generated manifest
├── www/                         Web app packaged into the APK
│   ├── index.html               shared with the web version (with native.css + native.js added)
│   ├── styles.css               shared with the web version
│   ├── game.js                  shared with the web version
│   ├── native.css               phone-only overrides (safe area, touch targets, forced portrait stack)
│   ├── native.js                Capacitor bridge (haptics, splash, back button, wake lock, status bar)
│   ├── manifest.webmanifest     PWA manifest (still useful in the WebView)
│   └── assets/                  every PNG / WebP / JPG from the game
└── android/                     generated by `npx cap add android` (not committed until you generate it)
```

## Prerequisites

Install once:

| Tool | Version | Where |
|------|---------|-------|
| **Node.js** | 18 LTS or newer | <https://nodejs.org> |
| **Android Studio** | Hedgehog (2023.1) or newer | <https://developer.android.com/studio> |
| **Android SDK** | API 34 (target) + API 24 (minSdk) | Install via Android Studio → SDK Manager |
| **Java** | JDK 17 | Ships with Android Studio, or install directly |

After Android Studio installs the SDK, set two env vars in your shell (`~/.zshrc` on macOS or `%USERPROFILE%\android-sdk` on Windows):

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"        # or your Windows/Linux path
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator"
```

## First-time setup

```bash
cd android
npm install                # pulls Capacitor + plugins
npx cap add android        # generates the android/ Android-Studio project
npx cap sync android       # copies www/ + plugin natives into the project
```

After the first `cap add android`, merge the settings from `AndroidManifest.overrides.xml` into `android/app/src/main/AndroidManifest.xml` (lock portrait, add VIBRATE + WAKE_LOCK, enable largeHeap, hardware acceleration, config-changes so orientation lock doesn't recreate the activity).

## Build a debug APK (for sideload / testing)

```bash
npm run sync              # re-copy www/ into the Android project after any code change
npm run build:debug       # produces android/app/build/outputs/apk/debug/app-debug.apk
```

Copy the `.apk` onto your phone (email it, put it on Google Drive, or use `adb install app-debug.apk`) and install. Debug APKs use a debug signing key so Play Store distribution won't accept them — that's normal.

## Build a release AAB (for the Play Store)

1. **Generate a signing key** (once, keep the `.jks` file safe — losing it means you can never update the app on the Play Store):
   ```bash
   keytool -genkey -v -keystore ~/bniine-release.jks \
     -keyalg RSA -keysize 2048 -validity 10000 -alias bniine
   ```
2. **Wire it into Gradle** — create `android/gradle.properties.local` (add to `.gitignore`):
   ```
   BNIINE_STORE_FILE=/absolute/path/to/bniine-release.jks
   BNIINE_STORE_PASSWORD=your-store-password
   BNIINE_KEY_ALIAS=bniine
   BNIINE_KEY_PASSWORD=your-key-password
   ```
   And in `android/app/build.gradle`, add:
   ```groovy
   android {
       signingConfigs {
           release {
               storeFile file(System.getenv('BNIINE_STORE_FILE') ?: project.findProperty('BNIINE_STORE_FILE'))
               storePassword System.getenv('BNIINE_STORE_PASSWORD') ?: project.findProperty('BNIINE_STORE_PASSWORD')
               keyAlias System.getenv('BNIINE_KEY_ALIAS') ?: project.findProperty('BNIINE_KEY_ALIAS')
               keyPassword System.getenv('BNIINE_KEY_PASSWORD') ?: project.findProperty('BNIINE_KEY_PASSWORD')
           }
       }
       buildTypes {
           release {
               signingConfig signingConfigs.release
               minifyEnabled true
               shrinkResources true
               proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
           }
       }
   }
   ```
3. **Build the release AAB**:
   ```bash
   npm run build:release
   ```
   Output: `android/app/build/outputs/bundle/release/app-release.aab`
4. Upload the `.aab` to Play Console → Testing → Internal testing (start there), then promote to Production.

## Live-preview during dev

To iterate without rebuilding the APK every time, point Capacitor at a live web server:

1. Serve `www/` from your dev machine: `cd www && python3 -m http.server 8080`
2. In `capacitor.config.ts`, uncomment `server.url` and set it to `http://YOUR-LAN-IP:8080` with `cleartext: true`
3. Run `npm run sync && npm run open:android`, hit Run in Android Studio, and the phone will reload whenever you save a file

## What Capacitor changes vs. the web version

Everything else is identical — same merge chains, same chef reactions, same tutorial, same daily challenge. Just three things behave better on the phone:

- **Haptics** — `navigator.vibrate` is transparently upgraded to native `Haptics.impact` (Light / Medium / Heavy) with `NotificationFeedbackType.Success` on level-ups and legendary discoveries. Feels stronger and cleaner than web vibration.
- **Splash + status bar** — the game boots into a native splash (warm brown backdrop, then the game's own animated splash), and the Android status bar is themed to match `#2B1810`.
- **Back button** — Android's hardware Back closes any open modal first, then the tutorial if it's up, and finally double-tap-to-exit with a "Press back again" toast.

## Play Store checklist

When you're ready to submit:

- [ ] App icon: `assets/apple-touch-icon.png` (180×180) or use `logo-bniiine-square.png` for the 512×512 Play Store hero
- [ ] Feature graphic: 1024×500 — use `bg-title-souk.jpg` cropped, or the `splash-hero.png` if you generate one
- [ ] Screenshots: at least 2 phone screenshots at 1080×1920 (portrait) — take these from a real device or emulator
- [ ] Short description (80 chars): "Merge spices into tagines, build your riad from Marrakech to Tunis."
- [ ] Full description (up to 4000 chars): reuse the opener from the web page's meta description
- [ ] Content rating: complete the IARC questionnaire — Bniine is casual, no violence, no gambling → likely PEGI 3 / everyone
- [ ] Privacy policy URL: required even if you don't collect data — a one-page policy on a static host works
- [ ] Target audience: pick "13+" unless you specifically add COPPA-compliant handling
- [ ] Data safety form: declare "no data collected" if you keep the LocalStorage-only setup (nothing leaves the device)

## Troubleshooting

- **`npx cap add android` fails with "Not a Capacitor project"** — make sure you ran `npm install` inside this `android/` folder first
- **APK builds but crashes on launch** — check `adb logcat *:E` on the phone; usually a missing plugin or a wrong `webDir` in `capacitor.config.ts`
- **Haptics do nothing on-device** — the plugin gracefully no-ops if the phone doesn't support vibration; confirm `<uses-permission android:name="android.permission.VIBRATE"/>` is in the manifest
- **Splash never hides** — `native.js` calls `SplashScreen.hide()` on boot; if you see the splash forever, the WebView never reached `native.js` — most often a JS error in `game.js`, so open Chrome DevTools remote debug (`chrome://inspect`) to see the console
